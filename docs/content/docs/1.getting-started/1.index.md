Nuxt Scripts 为 Nuxt 应用提供了一种一致的第三方脚本加载方式，并支持对加载时机、隐私和类型安全进行控制。

## 背景

`useHead` 非常适合用于添加 script 标签。当脚本必须处理服务端渲染（SSR）、延迟加载或类型化全局 API 时，配置会变得更加复杂。Nuxt Scripts 通过一个 API 处理这些情况。

### 第三方脚本的挑战

- 在客户端和服务端代码中安全运行。
- 选择浏览器加载脚本的时机。
- 避免阻塞渲染的工作和不必要的数据暴露。
- 验证配置并为脚本 API 提供类型支持。

### 第三方如何影响用户体验

分析工具、视频嵌入、地图和社交组件都会运行你无法控制的代码。单个集成可能开销不大；但多个集成可能与水合过程竞争、延迟交互并阻塞渲染。

[第三方脚本可能增加网络开销并延迟文档解析](https://web.dev/articles/third-party-javascript)，具体取决于它们的加载方式。[《2025 Web Almanac》中的第三方内容章节](https://almanac.httparchive.org/en/2025/third-parties)发现，即使页面访问的唯一第三方域名数量减少，请求数量仍有所增加。因此，仅统计供应商数量可能会低估它们为页面增加的工作量。

## Nuxt Scripts 功能

### 加载

- 默认情况下，脚本会使用 `onNuxtReady` 触发器，在水合完成后并处于空闲期间时加载。
- 根据同意状态、可见性、交互或应用状态触发脚本。
- 使用 [第一方模式](/docs/guides/first-party) 从你的源站提供受支持的脚本。

### 开发者 API

- 常见第三方应用的注册表条目。
- 用于分析集成的页面事件辅助工具。
- 脚本选项的输入验证。
- 类型安全且符合 SSR 规范的 API。

### 隐私

- 使用[注重隐私的代理](/docs/guides/first-party)最大限度地减少用户数据暴露。
- 集成同意管理。
- 提供隐私默认设置，例如 `crossorigin="anonymous"` 和 `referrerpolicy="no-referrer"`。
