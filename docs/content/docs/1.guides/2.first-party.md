## 问题所在

您网站加载的每个第三方脚本都会将用户直接连接到外部服务器。每个请求都会共享用户的 IP 地址，许多脚本更进一步：X Pixel 访问 9 个浏览器指纹 API（包括 `navigator.getBattery()`{lang="ts"}），设置 5 个跟踪 Cookie（`muc_ads`、`guest_id_marketing`、`guest_id_ads`、`personalization_id`、`guest_id`），并向 3 个独立的域名发送数据。Microsoft Clarity 在 3 个域名上读取 10 个指纹 API。即使是 154 KB 的 Google Analytics 也会发送可以跨站点关联的数据。

广告拦截器理所当然地会阻止这些请求，这破坏了依赖它们的网站的分析功能。

## 工作原理

第一方模式结合了三层自动协作的功能。每个脚本声明其支持的能力；模块零配置启用它们。

### 打包

在 `nuxt build` 期间，模块下载第三方脚本并将其保存为本地资产在 `/_scripts/assets/[hash].js`。在运行时，您的服务器（或 CDN）从您自己的域名提供这些文件，而不是原始的第三方 CDN。

这消除了额外的 DNS 查找，避免了 CORS 开销，意味着初始脚本加载永远不会触及第三方服务器。打包的脚本使用内容寻址哈希进行长期浏览器缓存。

### 反向代理

运行时请求（分析信标、像素触发、跟踪调用）被拦截并通过 Nitro 服务器路由在 `/_scripts/p/` 转发。模块在两个级别重写 URL：

1. **构建时 AST 重写**：打包脚本源中的第三方域名被替换为您的代理路径
2. **客户端运行时拦截**：插件修补 `fetch`、`sendBeacon`、`XMLHttpRequest` 和 `Image` 以捕获 AST 重写器错过的任何动态 URL

用户永远不会直接连接到第三方服务器，因此不会设置第三方 Cookie，广告拦截器也不会干扰。

### 匿名化

在转发代理请求之前，处理程序会剥离识别数据。IP 地址被匿名化到子网级别。敏感头（cookies、auth tokens）始终被移除。额外的匿名化（用户代理、屏幕尺寸、硬件指纹）因脚本而异，基于什么会破坏功能。

即使是最小化的匿名化，反向代理本身也能防止直接的浏览器连接，消除第三方 Cookie，并确保请求表现为同源。

## 使用方法

第一方模式**自动启用**于所有支持的脚本。将脚本添加到注册表会启用基础设施（代理路由、打包、类型、组合式函数）而无需自动加载它：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    registry: {
      // 仅基础设施 — 使用组合式函数在特定页面加载
      googleAnalytics: { id: 'G-XXXXXX' },
      metaPixel: { id: '123456' },

      // 基础设施 + 全局自动加载
      plausibleAnalytics: { domain: 'mysite.com', trigger: 'onNuxtReady' },
    }
  }
})
```

没有 `trigger` 的脚本仅作为基础设施：该模块为脚本准备任何支持的基础设施（代理路由、打包、组合式函数），但脚本仅在您在组件中调用组合式函数时加载。添加 `trigger` 以全局自动加载。

## 隐私层级

每个代理脚本默认根据其功能安全所需的匿名化级别设置隐私层级。三个层级涵盖所有脚本：

| 层级 | 匿名化内容 | 脚本 |
|------|-------------------|---------|
| **Full** | IP、用户代理、语言、屏幕、时区、硬件指纹 | Meta Pixel、TikTok Pixel、X Pixel、Snapchat Pixel、Reddit Pixel、LinkedIn Insight Tag |
| **Heatmap-safe** | IP、语言、硬件指纹（保留屏幕和用户代理用于会话回放） | Google Analytics、Microsoft Clarity、Hotjar |
| **IP only** | IP 地址匿名化到子网级别 | Plausible、PostHog、Umami、Fathom、CF Web Analytics、Vercel Analytics、Rybbit、Databuddy、Matomo、Ahrefs Web Analytics、Intercom、YouTube、Vimeo、Gravatar、Carbon Ads、Lemon Squeezy、Google AdSense、Calendly |

敏感请求头（`cookie`、`authorization`）无论层级如何都会被**始终**剥离。

### 六项隐私标识

每个层级映射到六个标识的组合：

| 标识 | 功能说明 |
|------|-------------|
| `ip` | 在头和负载参数中将 IP 地址匿名化到子网级别 |
| `userAgent` | 将 User-Agent 标准化为浏览器系列 + 主版本（例如 `Mozilla/5.0 (compatible; Chrome/131.0)`{lang="ts"}） |
| `language` | 将 Accept-Language 标准化为主要语言标签 |
| `screen` | 将屏幕分辨率、视口、硬件并发数和设备内存概括为常见桶 |
| `timezone` | 概括时区偏移和 IANA 时区名称 |
| `hardware` | 匿名化 canvas/webgl/audio 指纹、插件/字体列表、浏览器版本和设备信息 |

### 层级标识矩阵

| 标识 | 仅 IP | 热图安全 | 完全 |
|------|:-------:|:------------:|:----:|
| `ip` | :icon{name="i-heroicons-check"} | :icon{name="i-heroicons-check"} | :icon{name="i-heroicons-check"} |
| `userAgent` | | | :icon{name="i-heroicons-check"} |
| `language` | | :icon{name="i-heroicons-check"} | :icon{name="i-heroicons-check"} |
| `screen` | | | :icon{name="i-heroicons-check"} |
| `timezone` | | | :icon{name="i-heroicons-check"} |
| `hardware` | | :icon{name="i-heroicons-check"} | :icon{name="i-heroicons-check"} |

**仅 IP** 将 IP 匿名化到 /24 子网（城市级地理精度）。**热图安全** 剥离语言和硬件指纹，同时保留会话回放工具所需的用户代理和屏幕尺寸。**完全** 剥离所有内容，用于广告像素，其中没有分析报告依赖原始客户端数据。

### 全局覆盖

使用顶层 `privacy` 选项一次性覆盖所有每个脚本的隐私默认值：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    privacy: true, // 对所有脚本进行完全匿名化
  }
})
```

或者选择性覆盖特定标识：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    privacy: { ip: true }, // 对所有脚本匿名化 IP，其余使用每个脚本的默认值
  }
})
```

### 每个脚本的隐私覆盖

通过在注册表条目中添加 `privacy` 来覆盖特定脚本的隐私层级：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    registry: {
      // 对 Meta Pixel 进行完全匿名化（覆盖其默认值）
      metaPixel: { id: '123456', privacy: { ip: true, userAgent: true, screen: true } },
      // 对于您控制数据的自托管 PostHog 仅 IP
      posthog: { apiKey: 'phc_xxx', privacy: { ip: true } },
    }
  }
})
```

### 禁用匿名化

每个脚本或全局禁用匿名化。路由仍然适用（请求仍然通过您的服务器），仅数据剥离被关闭：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    privacy: false, // 不对任何脚本进行匿名化（路由仍然活跃）
  }
})
```

## 选择退出

### 每个脚本

在其注册表配置中使用 `proxy: false` 禁用特定脚本的代理：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    registry: {
      plausibleAnalytics: { domain: 'mysite.com', proxy: false },
      googleAnalytics: { id: 'G-XXXXXX' }, // 仍然被代理
    }
  }
})
```

在打包脚本上设置 `bundle: false` 也会禁用其代理。反向代理依赖于 AST URL 重写，这需要打包的脚本源。没有打包，就没有 URL 可重写。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    registry: {
      // 禁用此脚本的打包和代理
      googleAnalytics: { id: 'G-XXXXXX', bundle: false },
    }
  }
})
```

::callout{type="info"}
这不适用于使用配置注入而不是 URL 重写的仅代理脚本（PostHog、Matomo 等）。这些脚本可以在不打包的情况下被代理。
::

### 静态托管 (SSG)

反向代理需要一个**服务端运行时**。对于静态部署（`nuxt generate`），Nuxt Scripts 会自动禁用代理。脚本仍然会被打包并从您的域名提供，但运行时采集请求（分析信标、像素触发）会直接发送到第三方服务器。

如果您需要在静态托管上进行代理，请手动配置平台级重写。模式是 `/_scripts/p/<domain>/:path*` → `https://<domain>/:path*`：

```json [vercel.json]
{
  "rewrites": [
    { "source": "/_scripts/p/www.google-analytics.com/:path*", "destination": "https://www.google-analytics.com/:path*" },
    { "source": "/_scripts/p/www.googletagmanager.com/:path*", "destination": "https://www.googletagmanager.com/:path*" },
    { "source": "/_scripts/p/connect.facebook.net/:path*", "destination": "https://connect.facebook.net/:path*" }
  ]
}
```

相同的模式适用于 [Netlify](https://netlify.com)（`[[redirects]]` 带 `:splat`）和 Cloudflare Pages（`_redirects` 文件）。仅包含您使用的脚本的重写。检查 Nuxt DevTools → Scripts 或您的 Nitro 服务器日志以获取注册的确切域名。

::callout{type="warning"}
平台级重写绕过隐私匿名化层。代理处理程序仅在 Nitro 服务器运行时中运行。
::

## 代理端点安全

一些代理端点（Google 静态地图、Geocode、Gravatar、嵌入图片代理）会注入服务端 API 密钥或将请求转发到第三方服务。如果没有保护，任何发现这些端点的人都可以直接调用它们并消耗您的 API 配额。

### HMAC URL 签名

该模块提供可选的 HMAC 签名，用于锁定代理端点。启用后，仅接受在服务端生成的 URL（SSR 或预渲染期间）或附带有效页面令牌的请求。未签名请求将收到 `403`。

#### 设置

生成签名密钥：

```bash
npx @nuxt/scripts generate-secret
```

然后将其设置为环境变量：

```bash
NUXT_SCRIPTS_PROXY_SECRET=<your-secret>
```

或者直接配置它：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    security: {
      secret: process.env.NUXT_SCRIPTS_PROXY_SECRET,
    }
  }
})
```

#### 工作原理

该模块使用两种验证模式：

1. **URL 签名** 用于服务端渲染内容。在 SSR/预渲染期间，代理 URL 会包含 `sig` 参数：对路径和查询参数的 HMAC。代理端点在转发之前会验证签名。

2. **页面令牌** 用于客户端响应式更新。某些组件会在挂载后重新计算其代理 URL（例如测量元素尺寸）。服务器会在 SSR 负载中嵌入一个短期令牌（`_pt` + `_ts` 参数）。该令牌对任何代理路径上的任何参数都有效，并在 1 小时后过期。

#### 开发

在开发环境中，模块会自动生成一个密钥，并在首次运行时将其写入您的 `.env` 文件。您在本地开发时无需进行任何配置。

#### 生产环境

在部署环境中设置 `NUXT_SCRIPTS_PROXY_SECRET`。该密钥在所有副本之间以及构建/运行时之间必须保持一致，以便在预渲染时签名的 URL 仍然有效。

::callout{type="warning"}
如果没有密钥，代理端点仍可正常工作，但不会受到保护。当模块检测到存在已签名端点但没有密钥时，会在启动时记录警告。
::

#### 已签名端点

当您配置了密钥时，以下代理端点需要签名：

| 脚本 | 端点 |
|--------|-----------|
| **Google Maps** | `/_scripts/proxy/google-static-maps`、`/_scripts/proxy/google-maps-geocode` |
| **Gravatar** | `/_scripts/proxy/gravatar` |
| **Bluesky** | `/_scripts/embed/bluesky`、`/_scripts/embed/bluesky-image` |
| **Instagram** | `/_scripts/embed/instagram`、`/_scripts/embed/instagram-image`、`/_scripts/embed/instagram-asset` |
| **X (Twitter)** | `/_scripts/embed/x`、`/_scripts/embed/x-image` |

分析代理端点（Google Analytics、Plausible 等）不使用签名，因为它们只转发采集负载，并且不会暴露 API 密钥。

#### 配置参考

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    security: {
      // 用于签名代理 URL 的 HMAC 密钥。
      // 默认回退到 process.env.NUXT_SCRIPTS_PROXY_SECRET。
      secret: undefined,
      // 在开发模式下自动生成并将密钥持久化到 .env。
      // 设为 false 可禁用。
      autoGenerateSecret: true,
    }
  }
})
```

#### 故障排查

**签名 URL 在部署后返回 403**

密钥在构建时（URL 在预渲染期间签名）和运行时（服务器验证它们时）必须完全一致。如果您进行预渲染，请确保 `NUXT_SCRIPTS_PROXY_SECRET` 同时在构建环境和部署环境中可用。

**多个副本之间出现 403 错误**

所有服务器实例都必须共享同一个密钥。如果每个副本都生成自己的密钥，那么由一个实例签名的 URL 在另一个实例上将无法通过验证。请将 `NUXT_SCRIPTS_PROXY_SECRET` 设为所有副本共享的环境变量。

**`.env` 中出现意外的 `NUXT_SCRIPTS_PROXY_SECRET`**

只有在运行 `nuxt dev`、启用了已签名端点且未配置密钥时，模块才会写入此项。如果您只使用客户端脚本（分析、跟踪），模块不会生成密钥。若要完全阻止自动生成，请设置 `autoGenerateSecret: false`。

**页面令牌过期**

页面令牌有效期为 1 小时。如果用户将标签页打开超过该时间，客户端代理请求将开始返回 403。页面会在下次导航或刷新时恢复。

#### 静态生成和 SPA 模式

URL 签名需要服务器运行时来验证 HMAC 签名。有两种部署模式无法支持签名：

**`nuxt generate`（SSG）配合静态托管**：预渲染页面包含代理 URL，但运行时没有 Nitro 服务器来验证签名或转发请求。代理端点在静态主机（GitHub Pages、Cloudflare Pages 静态站点等）上将无法工作。如果您在预渲染时需要代理端点，请部署到支持预渲染和运行时请求处理的服务器目标（例如 Node、Cloudflare Workers、[Vercel](https://vercel.com)）。

**`ssr: false`（SPA 模式）**：没有服务端渲染，就没有机会签名 URL 或嵌入页面令牌。签名密钥位于仅服务端运行时配置中，客户端无法访问。若使用服务器部署，代理端点仍可正常工作，但请求将不会被签名。

::callout{type="info"}
在这两种情况下，模块都会自动检测到该限制并跳过签名设置。代理端点仍可正常工作，但不会受到保护。模块会在构建时记录警告。
::

## 支持的脚本

### 完全第一方（打包 + 代理）

这些脚本会在构建时下载，从您的域名提供，并通过您的服务器代理其收集请求：

| 类别 | 脚本 |
|----------|---------|
| **分析** | [Google Analytics](/scripts/google-analytics), [Plausible](/scripts/plausible-analytics), [Cloudflare Web Analytics](/scripts/cloudflare-web-analytics), [Umami](/scripts/umami-analytics), [Fathom](/scripts/fathom-analytics), [Rybbit](/scripts/rybbit-analytics), [Databuddy](/scripts/databuddy-analytics), [Ahrefs Web Analytics](/scripts/ahrefs-analytics), [Vercel Analytics](/scripts/vercel-analytics), [Microsoft Clarity](/scripts/clarity), [Hotjar](/scripts/hotjar) |
| **广告像素** | [Meta Pixel](/scripts/meta-pixel), [TikTok Pixel](/scripts/tiktok-pixel), [X Pixel](/scripts/x-pixel), [Snapchat Pixel](/scripts/snapchat-pixel), [Reddit Pixel](/scripts/reddit-pixel), [LinkedIn Insight Tag](/scripts/linkedin-insight), [Google AdSense](/scripts/google-adsense) |
| **视频** | [YouTube 播放器](/scripts/youtube-player), [Vimeo 播放器](/scripts/vimeo-player) |
| **实用工具** | [Intercom](/scripts/intercom), [Gravatar](/scripts/gravatar) |

### 仅代理（未打包）

该模块无法在构建时打包这些脚本，但仍通过您的服务器代理其收集请求：

| 脚本 | 工作原理 |
|--------|-------------|
| [PostHog](/scripts/posthog) | 通过 [npm](https://npmjs.com) 安装 SDK。通过 `apiHost` 配置自动注入代理端点。 |
| [Matomo](/scripts/matomo-analytics) | 自托管；打包会破坏脚本。为收集请求注册代理路由。 |
| [Carbon Ads](/scripts/carbon-ads) | 广告投放脚本。为收集请求注册代理路由。 |
| [Lemon Squeezy](/scripts/lemon-squeezy) | 支付组件。为收集请求注册代理路由。 |

### 仅打包（无代理）

这些脚本从您的域名提供，但其运行时请求仍然直接发送到第三方服务器：

| 脚本 | 为何不支持代理 |
|--------|--------------------------|
| [Google Tag Manager](/scripts/google-tag-manager) | GTM 的核心功能是在运行时加载其他脚本。这些运行时脚本绕过了构建时重写。 |
| [Segment](/scripts/segment) | SDK 动态构建 API URL，绕过请求拦截。 |
| [Crisp](/scripts/crisp) | SDK 在运行时从 `client.crisp.chat` 加载次要脚本和 CSS。 |
| [Mixpanel](/scripts/mixpanel-analytics) | 尚无代理集成。 |
| [Bing UET](/scripts/bing-uet) | 尚无代理集成。 |

仅打包脚本仍然受益于作为第一方资产提供（加载更快、无 CORS、减少页面加载时的外部连接）。

### 排除（仅直接加载）

这些脚本出于安全考虑需要直接浏览器连接：

| 脚本 | 原因 |
|--------|--------|
| **Stripe** | 欺诈检测需要真实的客户端指纹 |
| **PayPal** | 欺诈检测需要真实的客户端指纹 |
| **Google reCAPTCHA** | 机器人检测需要真实的浏览器指纹 |
| **Google Sign-In** | 认证完整性需要直接连接 |

这些脚本仍然正常工作，它们直接连接到第三方服务器而不是通过您的域名路由。

## Partytown（Web Worker）

通过为每个脚本设置 `partytown: true` 来将单个脚本加载到主线程之外：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/partytown', '@nuxt/scripts'],
  scripts: {
    registry: {
      plausibleAnalytics: { domain: 'example.com', partytown: true },
      fathomAnalytics: { site: 'XXXXX', partytown: true },
    }
  }
})
```

转发数组会为受支持的脚本自动配置。您必须安装 `@nuxtjs/partytown`。

::callout{icon="i-heroicons-exclamation-triangle" color="amber"}
GA4 与 Partytown 存在 [已知问题](https://github.com/BuilderIO/partytown/issues/583)。GTM 不兼容（需要 DOM 访问）。请考虑改用 Plausible、Fathom 或 Umami。
::

## 同意集成

第一方模式控制请求发送到*何处*。[同意触发器](/docs/guides/consent) 控制脚本*何时*加载。同时使用两者：

```vue
<script setup lang="ts">
const trigger = useScriptTriggerConsent()

useScriptGoogleAnalytics({
  id: 'G-XXXXXX',
  scriptOptions: { trigger }
})
</script>
```

### 第三方同意管理器

对于 OneTrust、CookieBot 或 Osano 等工具，将其同意信号绑定到响应式 ref：

```vue
<script setup lang="ts">
const hasAnalyticsConsent = ref(false)

// 示例：OneTrust 回调
onMounted(() => {
  window.OneTrust?.OnConsentChanged(() => {
    hasAnalyticsConsent.value = window.OnetrustActiveGroups?.includes('C0002') ?? false
  })
})

useScriptGoogleAnalytics({
  id: 'G-XXXXXX',
  scriptOptions: {
    trigger: useScriptTriggerConsent({ consent: hasAnalyticsConsent }),
  }
})
</script>
```

或者在注册表配置中使用 `trigger: 'manual'`，并在获得同意时调用 `$script.load()`{lang="ts"}：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
```

## 故障排除

| 问题 | 解决方案 |
|---------|-----|
| Analytics not tracking | 检查 DevTools → Network 中的 `/_scripts/p/` 请求。检查 Nitro 服务器日志中的代理错误 |
| Proxy not working on static site | Nuxt Scripts 会自动禁用 SSG 的反向代理。请使用平台重写规则或切换到服务器模式。参见 [静态托管](#static-hosting-ssg) |
| Stale script | `rm -rf .nuxt/cache/scripts` 然后重新构建 |
| Build download fails | 设置 `assets.fallbackOnSrcOnBundleFail: true`{lang="ts"} 以回退到直接加载 |
| Debugging | 打开 Nuxt DevTools → Scripts 查看代理路由和隐私状态 |
| Geo accuracy reduced | IP 匿名化使用 /24 子网，这会提供城市级别的准确度。按脚本或全局设置 `privacy: false` 以转发精确 IP |
| `bundle: false` disabled my proxy | 对于打包脚本，代理依赖 AST URL 重写，而这需要打包后的源代码。如果你只是想禁用代理，请改用 `proxy: false` |
| Per-script opt-out not working | 对于自动注入的脚本（Plausible、PostHog、Umami、Rybbit、Databuddy），请在注册表配置中使用 `proxy: false` |
