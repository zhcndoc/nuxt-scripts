title: 第一方模式
description: 通过您的域名路由第三方脚本流量，以提升隐私性和可靠性。
---

## 问题所在

您网站加载的每个第三方脚本都会将用户直接连接到外部服务器。每个请求都会共享用户的 IP 地址，许多脚本更进一步：X Pixel 访问 9 个浏览器指纹 API（包括 `navigator.getBattery()`{lang="ts"}），设置 5 个跟踪 Cookie（`muc_ads`、`guest_id_marketing`、`guest_id_ads`、`personalization_id`、`guest_id`），并向 3 个独立的域名发送数据。Microsoft Clarity 在 3 个域名上读取 10 个指纹 API。即使是 154 KB 的 Google Analytics 也会发送可以跨站点关联的数据。

广告拦截器理所当然地会阻止这些请求，这破坏了依赖它们的网站的分析功能。

## 您能获得什么

第一方模式提供两层保护：

**第 1 层：路由。** 该模块将脚本打包并从您的域名提供。收集请求通过您的服务器代理。用户从不连接到第三方服务器，因此不会设置第三方 Cookie，广告拦截器也不会干扰。

**第 2 层：匿名化。** 在将请求转发到原始端点之前，代理会剥离识别数据。IP 地址被匿名化到子网级别。敏感请求头（Cookie、认证令牌）始终被移除。额外的匿名化（用户代理、屏幕尺寸、硬件指纹）因脚本而异，取决于什么会破坏功能。

即使使用最小程度的匿名化，仅路由本身就能阻止直接浏览器连接，消除第三方 Cookie，并确保请求显示为同源。

## 使用方法

第一方模式**自动启用**于所有支持的脚本。将脚本添加到注册表会启用基础设施（代理路由、打包、类型、组合式函数）而无需自动加载它：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    registry: {
      // 仅基础设施 — 使用组合式函数在特定页面加载
      googleAnalytics: { id: 'G-XXXXXX' },
      metaPixel: { id: '123456' },

      // 基础设施 + 全局自动加载
      plausibleAnalytics: { domain: 'mysite.com', trigger: 'onNuxtReady' },
    }
  }
})
```

没有 `trigger` 的脚本仅作为基础设施：该模块为脚本准备任何支持的基础设施（代理路由、打包、组合式函数），但脚本仅在您在组件中调用组合式函数时加载。添加 `trigger` 以全局自动加载。

## 隐私层级

每个代理脚本默认采用基于该脚本功能安全匿名化级别的隐私层级。三个层级涵盖所有脚本：

| 层级 | 匿名化内容 | 脚本 |
|------|-------------------|---------|
| **完全** | IP、用户代理、语言、屏幕、时区、硬件指纹 | Meta Pixel、TikTok Pixel、X Pixel、Snapchat Pixel、Reddit Pixel |
| **热图安全** | IP、语言、硬件指纹（保留屏幕和用户代理以供会话回放使用） | Google Analytics、Microsoft Clarity、Hotjar |
| **仅 IP** | IP 地址匿名化到子网级别 | Plausible、PostHog、Umami、Fathom、CF Web Analytics、Vercel Analytics、Rybbit、Databuddy、Matomo、Intercom、YouTube、Vimeo、Gravatar、Carbon Ads、Lemon Squeezy、Google AdSense |

敏感请求头（`cookie`、`authorization`）无论层级如何都会被**始终**剥离。

### 六项隐私标识

每个层级映射到六个标识的组合：

| 标识 | 功能说明 |
|------|-------------|
| `ip` | 在请求头和数据参数中将 IP 地址匿名化到子网级别 |
| `userAgent` | 将 User-Agent 归一化为浏览器家族+主版本（如 `Mozilla/5.0 (compatible; Chrome/131.0)`{lang="ts"}） |
| `language` | 将 Accept-Language 归一化为主语言标签 |
| `screen` | 将屏幕分辨率、视口、硬件并发性和设备内存泛化到通用类别 |
| `timezone` | 泛化时区偏移和 IANA 时区名称 |
| `hardware` | 匿名化 canvas/webgl/audio 指纹、插件/字体列表、浏览器版本与设备信息 |

### 层级标识矩阵

| 标识 | 仅 IP | 热图安全 | 完全 |
|------|:-------:|:------------:|:----:|
| `ip` | :icon{name="i-heroicons-check"} | :icon{name="i-heroicons-check"} | :icon{name="i-heroicons-check"} |
| `userAgent` | | | :icon{name="i-heroicons-check"} |
| `language` | | :icon{name="i-heroicons-check"} | :icon{name="i-heroicons-check"} |
| `screen` | | | :icon{name="i-heroicons-check"} |
| `timezone` | | | :icon{name="i-heroicons-check"} |
| `hardware` | | :icon{name="i-heroicons-check"} | :icon{name="i-heroicons-check"} |

**仅 IP** 将 IP 匿名化为 /24 子网（城市级地理精度）。**热图安全** 剥离语言和硬件指纹，同时保留会话回放工具所需的用户代理和屏幕尺寸。**完全** 剥离所有内容，用于不依赖原始客户端数据进行分析报告的广告像素。

### 全局覆盖

一次性覆盖所有脚本的默认设置：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    proxy: {
      privacy: true, // 对所有脚本进行完全匿名化
    }
  }
})
```

或者选择性覆盖特定标识：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    proxy: {
      privacy: { ip: true }, // 对所有脚本匿名化 IP，其余使用每个脚本的默认设置
    }
  }
})
```

### 禁用匿名化

如果您需要转发原始数据（例如您控制数据的自托管 PostHog），可以按脚本或全局禁用匿名化：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    proxy: {
      privacy: false, // 不对任何脚本进行匿名化（路由仍然有效）
    }
  }
})
```

## 选择退出

### 全局禁用代理

要禁用所有代理（脚本直接从第三方服务器加载）：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    proxy: false
  }
})
```

### 按脚本退出

使用 `proxy: false` 为特定脚本禁用代理：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    registry: {
      plausibleAnalytics: { domain: 'mysite.com', proxy: false },
      googleAnalytics: { id: 'G-XXXXXX' }, // 仍然被代理
    }
  }
})
```

功能在扁平配置中与脚本输入一起设置：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    registry: {
      plausibleAnalytics: { domain: 'mysite.com', proxy: false },
    }
  }
})
```

## 支持的脚本

### 完全第一方（打包 + 代理）

这些脚本在构建时下载，从您的域名提供，并通过您的服务器代理其收集请求：

| 类别 | 脚本 |
|----------|---------|
| **分析** | [Google Analytics](/scripts/google-analytics)、[Plausible](/scripts/plausible-analytics)、[Cloudflare Web Analytics](/scripts/cloudflare-web-analytics)、[Umami](/scripts/umami-analytics)、[Fathom](/scripts/fathom-analytics)、[Rybbit](/scripts/rybbit-analytics)、[Databuddy](/scripts/databuddy-analytics)、[Vercel Analytics](/scripts/vercel-analytics)、[Microsoft Clarity](/scripts/clarity)、[Hotjar](/scripts/hotjar) |
| **广告像素** | [Meta Pixel](/scripts/meta-pixel)、[TikTok Pixel](/scripts/tiktok-pixel)、[X Pixel](/scripts/x-pixel)、[Snapchat Pixel](/scripts/snapchat-pixel)、[Reddit Pixel](/scripts/reddit-pixel)、[Google AdSense](/scripts/google-adsense) |
| **视频** | [YouTube Player](/scripts/youtube-player)、[Vimeo Player](/scripts/vimeo-player) |
| **工具** | [Intercom](/scripts/intercom)、[Gravatar](/scripts/gravatar) |

### 仅代理（未打包）

该模块无法在构建时打包这些脚本，但仍通过您的服务器代理其收集请求：

| 脚本 | 工作原理 |
|--------|-------------|
| [PostHog](/scripts/posthog) | 通过 [npm](https://npmjs.com) 安装 SDK。通过 `apiHost` 配置自动注入代理端点。 |
| [Matomo](/scripts/matomo-analytics) | 自托管；打包会破坏脚本。为收集请求注册代理路由。 |
| [Carbon Ads](/scripts/carbon-ads) | 广告投放脚本。为收集请求注册代理路由。 |
| [Lemon Squeezy](/scripts/lemon-squeezy) | 支付组件。为收集请求注册代理路由。 |

### 仅打包（无代理）

这些脚本从您的域名提供，但其运行时请求仍然直接发送到第三方服务器：

| 脚本 | 为何不支持的代理 |
|--------|--------------------------|
| [Google Tag Manager](/scripts/google-tag-manager) | GTM 的核心功能是在运行时加载其他脚本。这些运行时脚本绕过了构建时重写。 |
| [Segment](/scripts/segment) | SDK 动态构建 API URL，绕过请求拦截。 |
| [Crisp](/scripts/crisp) | SDK 在运行时从 `client.crisp.chat` 加载次要脚本和 CSS。 |
| [Mixpanel](/scripts/mixpanel-analytics) | 尚无代理集成。 |
| [Bing UET](/scripts/bing-uet) | 尚无代理集成。 |

仅打包脚本仍然受益于作为第一方资产提供（加载更快、无 CORS、减少页面加载时的外部连接）。

### 排除（仅直接加载）

这些脚本出于安全考虑需要直接浏览器连接：

| 脚本 | 原因 |
|--------|--------|
| **Stripe** | 欺诈检测需要真实的客户端指纹 |
| **PayPal** | 欺诈检测需要真实的客户端指纹 |
| **Google reCAPTCHA** | 机器人检测需要真实的浏览器指纹 |
| **Google Sign-In** | 认证完整性需要直接连接 |

这些脚本仍然正常工作，它们直接连接到第三方服务器而不是通过您的域名路由。

## Partytown（Web Worker）

通过为每个脚本设置 `partytown: true` 来将单个脚本加载到主线程之外：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/partytown', '@nuxt/scripts'],
  scripts: {
    registry: {
      plausibleAnalytics: { domain: 'example.com', partytown: true },
      fathomAnalytics: { site: 'XXXXX', partytown: true },
    }
  }
})
```

转发数组会为支持的脚本自动配置。您必须安装 `@nuxtjs/partytown`。

::callout{icon="i-heroicons-exclamation-triangle" color="amber"}
GA4 与 Partytown 存在[已知问题](https://github.com/BuilderIO/partytown/issues/583)。GTM 不兼容（需要 DOM 访问）。请考虑改用 Plausible、Fathom 或 Umami。
::

## 静态托管

第一方模式需要为代理端点提供**服务器运行时**。对于静态部署（`nuxt generate`），脚本仍然会使用重写后的 URL 进行打包，但你需要手动配置平台重写规则。

重写模式为 `/_scripts/p/<domain>/:path*` → `https://<domain>/:path*`。查看 Nuxt DevTools → Scripts 或你的 Nitro 服务器日志，了解为你的脚本注册的确切域名。

[Vercel](https://vercel.com) 示例：

```json [vercel.json]
{
  "rewrites": [
    { "source": "/_scripts/p/www.google-analytics.com/:path*", "destination": "https://www.google-analytics.com/:path*" },
    { "source": "/_scripts/p/www.googletagmanager.com/:path*", "destination": "https://www.googletagmanager.com/:path*" },
    { "source": "/_scripts/p/connect.facebook.net/:path*", "destination": "https://connect.facebook.net/:path*" }
  ]
}
```

同样的模式适用于 [Netlify](https://netlify.com)（使用 `:splat` 的 `[[redirects]]`）和 Cloudflare Pages（`_redirects` 文件）。只包含你所使用脚本的重写规则。

::callout{type="warning"}
平台级重写会绕过隐私匿名层。代理处理程序仅在 Nitro 服务器运行时中运行。
::

## 同意集成

第一方模式控制请求发送到*何处*。[Consent triggers](/docs/guides/consent) 控制脚本*何时*加载。同时使用两者：

```vue
<script setup lang="ts">
const trigger = useScriptTriggerConsent()

useScriptGoogleAnalytics({
  id: 'G-XXXXXX',
  scriptOptions: { trigger }
})
</script>
```

### 第三方同意管理器

对于 OneTrust、CookieBot 或 Osano 等工具，将其同意信号绑定到响应式 ref：

```vue
<script setup lang="ts">
const hasAnalyticsConsent = ref(false)

// 示例：OneTrust 回调
onMounted(() => {
  window.OneTrust?.OnConsentChanged(() => {
    hasAnalyticsConsent.value = window.OnetrustActiveGroups?.includes('C0002') ?? false
  })
})

useScriptGoogleAnalytics({
  id: 'G-XXXXXX',
  scriptOptions: {
    trigger: useScriptTriggerConsent({ consent: hasAnalyticsConsent }),
  }
})
</script>
```

或者在注册表配置中使用 `trigger: 'manual'`，并在获得同意时调用 `$script.load()`{lang="ts"}：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    registry: {
      // 仅基础架构，在获得同意后手动加载
      googleAnalytics: { id: 'G-XXXXXX' },
    }
  }
})
```

```vue [app.vue]
<script setup lang="ts">
const { $script } = useScriptGoogleAnalytics()

function onConsentGranted() {
  $script.load()
}
</script>
```

查看 [Consent Management Guide](/docs/guides/consent) 了解 `useScriptTriggerConsent()`{lang="ts"} 的完整细节。

::callout{type="info"}
第一方模式**不会**绕过 GDPR 同意要求。在加载跟踪脚本之前，你仍然需要用户同意。
::

## 故障排除

| 问题 | 解决方案 |
|---------|-----|
| Analytics 未跟踪 | 检查 DevTools → Network 中的 `/_scripts/p/` 请求。检查 Nitro 服务器日志中的代理错误 |
| 脚本过期 | 执行 `rm -rf .nuxt/cache/scripts` 并重新构建 |
| 构建下载失败 | 设置 `assets.fallbackOnSrcOnBundleFail: true`{lang="ts"} 以回退到直接加载 |
| 调试 | 打开 Nuxt DevTools → Scripts 查看代理路由和第一方状态 |
| 地理位置精确度降低 | IP 匿名化使用 /24 子网，可提供城市级别的精确度。按脚本设置 `privacy: false` 或全局设置以转发确切的 IP |
| 按脚本选择退出无效 | 对于自动注入的脚本（Plausible、PostHog、Umami、Rybbit、Databuddy），在注册表配置中使用 `proxy: false` |
