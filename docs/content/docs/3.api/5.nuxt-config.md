## `registry`{lang="ts"}

- 类型: `ScriptRegistry`

配置要启用哪些脚本。将脚本添加到注册表会启用基础设施（代理路由、类型、打包、组合式函数自动导入），但不会自动加载。添加 `trigger` 可全局自动加载。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    registry: {
      // 仅基础设施（组合式函数驱动）
      googleAnalytics: { id: 'G-XXXXXX' },
      // 基础设施 + 全局自动加载
      plausibleAnalytics: { domain: 'mysite.com', trigger: 'onNuxtReady' },
      // 退出代理
      posthog: { apiKey: 'phc_xxx', proxy: false },
      // 测试存根（不加载脚本，跳过验证）
      clarity: 'mock',
      // 禁用脚本
      hotjar: false,
    }
  }
})
```

可以在配置对象的顶层设置每个脚本的功能标志（`trigger`、`proxy`、`bundle`、`partytown`），与脚本的输入字段并列。

有关更多详细信息，请参阅 [脚本注册表](/scripts)。

### 环境变量

注册表输入字段通过 Nuxt 的 `runtimeConfig.public` 机制解析。在 `runtimeConfig.public.scripts` 下定义字段，并通过环境变量覆盖：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      scripts: {
        googleAnalytics: { id: '' }, // NUXT_PUBLIC_SCRIPTS_GOOGLE_ANALYTICS_ID
        posthog: { apiKey: '' }, // NUXT_PUBLIC_SCRIPTS_POSTHOG_API_KEY
        crisp: { id: '' }, // NUXT_PUBLIC_SCRIPTS_CRISP_ID
      }
    }
  }
})
```

这会将机密信息保留在 `nuxt.config.ts` 之外，并允许按环境进行覆盖。

## `proxy`{lang="ts"}

- 类型: `false | { prefix?: string, privacy?: ProxyPrivacyInput }`{lang="ts"}
- 默认值: `undefined`（自动推断）

控制反向代理基础设施，用于通过你的域名路由第三方脚本请求。

默认情况下，当任何已配置的脚本具有 `proxy` 功能时，代理会自动启用。设置为 `false` 可全局禁用所有代理。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    // 禁用所有代理
    proxy: false,

    // 或自定义代理设置
    proxy: {
      prefix: '/_analytics', // 自定义代理路径前缀（默认: '/_scripts/p'）
      privacy: true, // 所有代理脚本的全局隐私覆盖
    }
  }
})
```

有关隐私控制的详细信息，请参阅 [第一方指南](/docs/guides/first-party)。

### 每个脚本的功能

存在于注册表中会启用基础设施（代理路由、类型、打包、组合式函数自动导入）。仅当显式设置 `trigger` 时，脚本才会全局自动加载。所有功能标志（`trigger`、`proxy`、`bundle`、`partytown`）都可以在配置对象的顶层设置：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    registry: {
      // 仅基础设施（组合式函数驱动）
      googleAnalytics: { id: 'G-XXXXXX' },
      // 基础设施 + 全局自动加载
      plausibleAnalytics: { domain: 'mysite.com', trigger: 'onNuxtReady' },
      // 为此脚本退出代理
      posthog: { proxy: false },
      // 为此脚本启用 Partytown
      fathomAnalytics: { site: 'XXXXX', partytown: true, trigger: 'onNuxtReady' },
    }
  }
})
```

### Partytown（Web Worker）:badge[实验性]{color="amber"}

使用 [Partytown](https://partytown.qwik.dev/) 在 Web Worker 中加载单个脚本。在脚本的选项中设置 `partytown: true`：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/partytown', '@nuxt/scripts'],
  scripts: {
    registry: {
      plausibleAnalytics: { domain: 'example.com', partytown: true },
      fathomAnalytics: { site: 'XXXXX', partytown: true },
      umamiAnalytics: { websiteId: 'xxx', partytown: true },
    }
  }
})
```

::callout{icon="i-heroicons-exclamation-triangle" color="amber"}
你必须安装 [`@nuxtjs/partytown`](https://github.com/nuxt-modules/partytown)。Nuxt 会为支持的脚本自动配置 `forward` 数组。
::

#### 支持的脚本

配置了自动转发的脚本：
- `googleAnalytics`, `plausibleAnalytics`, `fathomAnalytics`, `umamiAnalytics`, `matomoAnalytics`, `segment`
- `metaPixel`, `xPixel`, `tiktokPixel`, `snapchatPixel`, `redditPixel`
- `cloudflareWebAnalytics`

#### 限制

::callout{icon="i-heroicons-x-circle" color="red"}
**不兼容的脚本**：以下内容由于需要 DOM 访问而无法与 Partytown 一起工作：
- **标签管理器**：Google Tag Manager、Adobe Launch
- **会话重放**：Hotjar、Clarity、FullStory、LogRocket
- **聊天小部件**：Intercom、Crisp、Drift、HubSpot Chat
- **视频播放器**：[YouTube](https://youtube.com)、Vimeo 嵌入
- **A/B 测试**：Optimizely、VWO、Google Optimize
::

::callout{icon="i-heroicons-exclamation-triangle" color="amber"}
**通用限制**：
- 脚本不能直接访问或修改 DOM
- `document.cookie` 访问需要附加的 Partytown 配置
- 调试更复杂（代码在 Web Worker 中运行）
- 与主线程执行相比，某些脚本可能存在时序差异
- localStorage/sessionStorage 访问可能需要转发配置
::

## `defaultScriptOptions`{lang="ts"}

- 类型: `NuxtUseScriptOptions`
- 默认值: `{ trigger: 'onNuxtReady' }`

脚本的默认选项。有关更多详细信息，请参阅 [useScript](/docs/api/use-script) 文档。

## `globals`{lang="ts"}

- 类型: `(NuxtUseScriptInput | [NuxtUseScriptInput, NuxtUseScriptOptions])[]`
- 默认值: `[]`

应在所有页面加载的全局脚本。这是针对 [useScript](/docs/api/use-script) 组合式函数的配置。

有关更多详细信息，请参阅 [全局](/docs/guides/global) 文档。

## `defaultScriptOptions.warmupStrategy`{lang="ts"}

- 类型: `false | 'preload' | 'preconnect' | 'dns-prefetch'`{lang="ts"}
- 默认值: `false`

控制浏览器在脚本加载之前如何预热与脚本来源的连接：

- `'preload'` 插入 `<link rel="preload">`{lang="html"} 标签，提前下载脚本。最适合在页面加载后不久加载的脚本。
- `'preconnect'` 与脚本的来源建立早期连接（DNS + TCP + TLS）。用于稍后加载的脚本。
- `'dns-prefetch'` 解析 DNS。最轻量的选项，适用于可能加载也可能不加载的脚本。
- `false` 完全禁用预热。当模块打包脚本（已从你的域名提供）时使用。

::callout{type="info"}
当第一方模式打包脚本时，`preconnect` 和 `dns-prefetch` 会自动回退到 `false`，因为你的来源已经提供了该脚本。
::

## `enabled`{lang="ts"}

- 类型: `boolean`
- 默认值: `true`

禁用 Nuxt Scripts 模块。

## `debug`{lang="ts"}

- 类型: `boolean`
- 默认值: `false`

启用以查看调试日志。

## `assets`{lang="ts"}

- 类型: `object`
- 默认值: `{ prefix: '/_scripts/', strategy: 'public' }`

控制脚本打包和由 Nuxt 提供的方式。

有关更多详细信息，请参阅 [打包](/docs/guides/bundling) 文档。

## `assets.fallbackOnSrcOnBundleFail`{lang="ts"}

- 类型: `boolean`
- 默认值: `false`

启用时，当打包失败时回退到远程 src URL。默认情况下，如果第三方脚本无法下载，打包过程将停止。

## `assets.fetchOptions`{lang="ts"}

- 类型: `object`
- 默认值: `{ retry: 3, retryDelay: 2000, timeout: 15_000 }`

下载脚本时传递给 fetch 函数的选项。

## `assets.integrity`{lang="ts"}

- 类型: `boolean | 'sha256' | 'sha384' | 'sha512'`
- 默认值: `false`

启用自动子资源完整性 (SRI) 哈希生成以用于打包的脚本。启用后，会计算每个打包脚本的加密哈希，并注入 `integrity` 属性以及 `crossorigin="anonymous"`。

有关更多详细信息，请参阅 [打包 - 子资源完整性](/docs/guides/bundling#subresource-integrity-sri) 文档。
