## v1 新特性

v1 专注于**隐私**和**性能**：通过你自己的域名路由分析脚本，将脚本移出主线程，并在服务器端渲染社交嵌入内容。

### 第一方模式：专注于隐私的代理 ([#577](https://github.com/nuxt/scripts/pull/577))

第三方脚本会暴露数据，使得跨站点指纹识别用户成为可能。每个请求都会共享用户的 IP 地址，并且脚本可以设置第三方 Cookie 用于跨站点跟踪。

第一方模式充当反向代理：脚本在构建时打包并从你的域名提供服务，而运行时收集请求则通过 Nitro 服务器路由转发并自动匿名化。对于支持此功能的脚本，它是**自动启用**的，零配置：

```ts
export default defineNuxtConfig({
  scripts: {
    registry: {
      googleAnalytics: { id: 'G-XXXXXX' },
      metaPixel: { id: '123456' },
    }
  }
})
```

- **用户 IP 保持私密**：第三方看到的是你服务器的 IP
- **无第三方 Cookie**：请求是同源的
- **兼容广告拦截器**：请求表现为第一方
- 每个脚本可选退出：在注册表条目中设置 `proxy: false`

详见 [第一方模式指南](/docs/guides/first-party)。

### Partytown 支持 ([#576](https://github.com/nuxt/scripts/pull/576))

使用 Web Workers 将脚本加载到主线程之外。为每个脚本设置 `partytown: true`：

```ts
export default defineNuxtConfig({
  modules: ['@nuxtjs/partytown', '@nuxt/scripts'],
  scripts: {
    registry: {
      plausibleAnalytics: { domain: 'example.com', partytown: true },
      fathomAnalytics: { site: 'XXXXX', partytown: true },
    }
  }
})
```

转发数组会为支持的脚本自动配置。

::callout{icon="i-heroicons-exclamation-triangle" color="amber"}
GA4 与 Partytown 存在 [已知问题](https://github.com/BuilderIO/partytown/issues/583)。GTM 不兼容。请考虑使用 Plausible、Fathom 或 Umami 替代。
::

### SSR 社交嵌入 ([#590](https://github.com/nuxt/scripts/pull/590))

在服务器端渲染 X、Instagram 和 Bluesky 嵌入内容，无需加载第三方 JavaScript。

在你的 `nuxt.config` 中启用你需要的嵌入：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    registry: {
      xEmbed: { trigger: 'onNuxtReady' },
      instagramEmbed: { trigger: 'onNuxtReady' },
      blueskyEmbed: { trigger: 'onNuxtReady' },
    },
  },
})
```

```vue
<ScriptXEmbed tweet-id="1754336034228171055">
  <template #default="{ userName, text, likesFormatted }">
    <!-- 通过作用域插槽完全控制样式 -->
  </template>
</ScriptXEmbed>

<ScriptInstagramEmbed post-url="https://instagram.com/p/ABC123/">
  <template #default="{ html }">
    <div v-html="html" />
  </template>
</ScriptInstagramEmbed>

<ScriptBlueskyEmbed post-url="https://bsky.app/profile/...">
  <template #default="{ html }">
    <div v-html="html" />
  </template>
</ScriptBlueskyEmbed>
```

- 零第三方 JavaScript
- X/Instagram/Bluesky 不设置 Cookie
- 不共享用户 IP
- 所有内容都从你的域名提供

### 同意触发器撤销 ([#631](https://github.com/nuxt/scripts/pull/631))

`useScriptTriggerConsent()`{lang="ts"} 组合式函数现在支持在运行时撤销同意：

```ts
const trigger = useScriptTriggerConsent()
useScriptGoogleTagManager({ id: 'GTM-XXX', scriptOptions: { trigger } })

trigger.accept() // 授予同意
trigger.revoke() // 撤销同意
trigger.consented // Ref<boolean>
```

```ts
const script = useScript('/third-party.js')
await script.reload()
```

## 注册表配置变更

v1 重新设计了注册表条目的工作方式。关键变化：**存在即启用基础设施，`trigger` 启用自动加载**。

### 没有触发器脚本不再自动加载

在 v0 中，任何配置的脚本都会全局自动加载。在 v1 中，脚本需要明确的 `trigger` 才能自动加载。如果没有，脚本会注册基础设施（代理路由、类型、打包），但**不会**在页面上加载。

如果你在 v0 中有这样的配置：

```ts [v0 nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    registry: {
      googleAnalytics: { id: 'G-XXXXXX' },
    }
  }
})
```

你在 v1 中需要添加一个触发器：

```ts [v1 nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    registry: {
      googleAnalytics: { id: 'G-XXXXXX', trigger: 'onNuxtReady' },
    }
  }
})
```

如果你只需要基础设施而不需要在页面上加载脚本，请显式设置 `trigger: false`。这会注册代理路由、TypeScript 类型和打包配置，但不会注入 `<script>`{lang="html"} 标签。当你通过组件或组合式函数自己加载脚本时很有用。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    registry: {
      googleAnalytics: { id: 'G-XXXXXX', trigger: false },
    }
  }
})
```

::callout{icon="i-heroicons-exclamation-triangle" color="amber"}
如果你提供的配置值没有 `trigger`，将出现构建警告。设置 `trigger: 'onNuxtReady'` 以自动加载，或设置 `trigger: false` 仅用于基础设施。
::

### 配置迁移

| v0 | v1 | 变更内容 |
|----|-----|--------------|
| `{ id: '...' }` | `{ id: '...', trigger: 'onNuxtReady' }` | 添加明确的 `trigger` 以自动加载。`true` 简写、`bundle` 选项和数组元组语法也被带有 `trigger` 的扁平配置取代。 |
| `'mock'` | `'mock'` | 不变；创建用于测试的存根 |

### 扁平配置语法

v1 支持扁平配置语法。`trigger`、`proxy`、`bundle` 和 `partytown` 可以在顶层设置：

```ts [v0 nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    registry: {
      googleAnalytics: [{ id: 'G-xxx' }, { trigger: 'onNuxtReady' }],
      plausibleAnalytics: [{ domain: 'mysite.com' }, { bundle: true }],
    }
  }
})
```

```ts [v1 nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    registry: {
      googleAnalytics: { id: 'G-xxx', trigger: 'onNuxtReady' },
      plausibleAnalytics: { domain: 'mysite.com' },
    }
  }
})
```

### 环境变量

注册表配置字段通过 Nuxt 标准的 `runtimeConfig.public` 机制解析。将你的脚本配置添加到 `runtimeConfig.public.scripts` 下，并通过环境变量引用：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      scripts: {
        googleAnalytics: { id: '' }, // NUXT_PUBLIC_SCRIPTS_GOOGLE_ANALYTICS_ID
        posthog: { apiKey: '' }, // NUXT_PUBLIC_SCRIPTS_POSTHOG_API_KEY
      }
    }
  }
})
```

### 使用 `'mock'` 进行测试

使用 `'mock'` 注册脚本存根而不加载任何内容。这会创建基础设施（类型、组合式函数自动导入），设置 `trigger: 'manual'` 并禁用验证：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  scripts: {
    registry: {
      googleAnalytics: 'mock',
    }
  }
})
```

## 重大变更

### PayPal SDK v6 ([#628](https://github.com/nuxt/scripts/pull/628))

已迁移到 PayPal JavaScript SDK v6。组件 API 发生了重大变化：

- **SDK URL 现在使用 v6 端点**（`/web-sdk/v6/core`）
- **新的认证模式**：`clientId`（可选 `clientToken`）或单独使用 `clientToken`
- **沙盒模式在开发环境中默认设为 `true`**

### YouTube 播放器

#### 宽高比

使用 `ratio` 属性代替从 `width/height` 推导：

```diff
<ScriptYouTubePlayer
  video-id="..."
-  :width="1280"
-  :height="720"
+  ratio="16/9"
/>
```

默认为 `16/9`。

#### 占位图片

默认的 `object-fit` 从 `contain` 改为 `cover`：

```vue
<ScriptYouTubePlayer video-id="..." placeholder-object-fit="contain" />
```

#### 多个播放器

播放器实例现在已正确隔离。移除任何针对多个播放器的变通方案。

### Google Maps 组件整合

v1 整合了 Google Maps 标记组件并移除了遗留的 `google.maps.Marker` API。

#### `ScriptGoogleMapsAdvancedMarkerElement` → `ScriptGoogleMapsMarker`

`ScriptGoogleMapsAdvancedMarkerElement` 已重命名为 `ScriptGoogleMapsMarker`。旧名称仍然有效但会发出弃用警告。

```diff
-<ScriptGoogleMapsAdvancedMarkerElement :position="{ lat: 0, lng: 0 }" />
+<ScriptGoogleMapsMarker :position="{ lat: 0, lng: 0 }" />
```

#### 已移除 `ScriptGoogleMapsPinElement`

请改用 `ScriptGoogleMapsMarker` 上的 `#content` 插槽：

```diff
-<ScriptGoogleMapsAdvancedMarkerElement :position="pos">
-  <ScriptGoogleMapsPinElement :options="{ background: 'red' }" />
-</ScriptGoogleMapsAdvancedMarkerElement>
+<ScriptGoogleMapsMarker :position="pos">
+  <template #content>
+    <div class="custom-pin" style="background: red;">📍</div>
+  </template>
+</ScriptGoogleMapsMarker>
```

#### 已从 `ScriptGoogleMaps` 移除 `markers` 和 `centerMarker` 属性

请改用子 `ScriptGoogleMapsMarker` 组件：

```diff
-<ScriptGoogleMaps
-  :center="center"
-  :markers="[{ position: { lat: 0, lng: 0 } }]"
-  center-marker
-/>
+<ScriptGoogleMaps :center="center">
+  <ScriptGoogleMapsMarker :position="center" />
+  <ScriptGoogleMapsMarker :position="{ lat: 0, lng: 0 }" />
+</ScriptGoogleMaps>
```

#### Top-Level `center` and `zoom` Props Deprecated

The top-level `center` and `zoom` props on `<ScriptGoogleMaps>`{lang="html"} are deprecated in favour of passing them via `mapOptions`. Both APIs still work; using the legacy form emits a dev-mode warning. When both are set, `mapOptions` wins.

```diff
-<ScriptGoogleMaps :center="{ lat, lng }" :zoom="12" />
+<ScriptGoogleMaps :map-options="{ center: { lat, lng }, zoom: 12 }" />
```

#### Template Ref `googleMaps` Renamed to `mapsApi`

The `googleMaps` template-ref key on `<ScriptGoogleMaps>`{lang="html"} has been renamed to `mapsApi` to better reflect what it holds (the `google.maps` API namespace, not the component itself). The old key still works as a deprecated alias and emits a one-shot dev-mode warning when read.

```diff
 const mapRef = ref()
 onMounted(() => {
-  console.log(mapRef.value?.googleMaps)
+  console.log(mapRef.value?.mapsApi)
 })
```

The same rename applies to `<ScriptGoogleMapsOverlayView>`{lang="html"}: its exposed `overlay` key is now `overlayView`, with `overlay` kept as a deprecated alias.

```diff
 const overlayRef = ref()
 onMounted(() => {
-  console.log(overlayRef.value?.overlay)
+  console.log(overlayRef.value?.overlayView)
 })
```

#### `<ScriptGoogleMapsOverlayView>`{lang="html"} DOM Structure

The overlay view now renders an extra wrapper element. The structure is `anchor div → content div → slot`, where the anchor handles positioning (Google Maps reparents it into a pane on mount) and the content div carries `data-state` plus any forwarded `class`/attrs.

CSS that targets `[data-state="open"]` on the slot's root element should move to a class on the `<ScriptGoogleMapsOverlayView>`{lang="html"} itself, since the data-state attribute now lives on the internal content div rather than propagating into the slot's first child.

```diff
 <template>
-  <ScriptGoogleMapsOverlayView v-model:open="open">
-    <div class="overlay-popup">
-      ...
-    </div>
-  </ScriptGoogleMapsOverlayView>
+  <ScriptGoogleMapsOverlayView class="overlay-popup" v-model:open="open">
+    ...
+  </ScriptGoogleMapsOverlayView>
 </template>

 <style scoped>
-.overlay-popup[data-state="open"] { animation: ... }
+/* Use :deep() in scoped styles since the class lands on a child component's element */
+:deep(.overlay-popup[data-state="open"]) { animation: ... }
 </style>
```

### Google Maps Static Placeholder ([#673](https://github.com/nuxt/scripts/pull/673))

v1 将内置的静态地图占位图提取为独立的 [`<ScriptGoogleMapsStaticMap>`{lang="html"}] 组件。这从 `<ScriptGoogleMaps>`{lang="html"} 中移除了以下属性：

- `placeholderOptions`
- `placeholderAttrs`
- `aboveTheFold`

#placeholder 插槽不再传递 `placeholder` URL 字符串。现在默认为空。

```diff
<!-- 之前 -->
<ScriptGoogleMaps
  :center="center"
  :zoom="7"
  above-the-fold
  :placeholder-options="{ maptype: 'satellite' }"
  :placeholder-attrs="{ class: 'rounded' }"
/>

<!-- 之后 -->
+<ScriptGoogleMaps :center="center" :zoom="7">
+  <template #placeholder>
+    <ScriptGoogleMapsStaticMap
      :center="center"
      :zoom="7"
      loading="eager"
      maptype="satellite"
      :img-attrs="{ class: 'rounded' }"
    />
  </template>
+</ScriptGoogleMaps>
```

使用新组件独立用于商店定位器、联系页面和路线预览，而无需加载交互式 Maps API。

### Google Tag Manager

#### onBeforeGtmStart 回调

现在会为缓存的/预初始化的脚本触发。防止多次调用：

```ts
let initialized = false
useScriptGoogleTagManager({
  onBeforeGtmStart: (gtag) => {
    if (initialized)
      return
    initialized = true
    // 你的初始化代码
  }
})
```
